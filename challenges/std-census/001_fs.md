# std/fs — 113 lines, two tors, one commented-out future

## The table

| tor | classification | evidence |

| `read-lines { path }` | **live** (aspirational-flagged) | 90 `std/fs:read-lines` call sites; plain `~proc`, no transform routing found (grep for emitted names across `koru_std/*.kz` returns only a doc comment in `io.kz`) |
| `write { path, content }` | **live** | 3 `std/fs:write` call sites; plain `~proc` |

## Seams

- **`write` cannot refuse creation** — `createFile` silently creates a missing
  path and truncates an existing one; the only arms are `| written` and
  `| failed string`. No `| refused`, no `exists`-gate, no append. (kopium
  wired/holes/6, settler re-confirmed open the same day: missing file
  created, `written` returned.) **→010** — a refusal arm is the honest fix.
- **The file API is split across `io` and `fs` by verb, not domain.** Whole-file
  read is `io:read-file` (110 sites), per-line file read is `fs:read-lines`
  (90), stdin lines are `io:read-lines` (2, no path param — the same slurp
  machinery reading `stdin()`), file write is `fs:write` (3). A consumer
  reading files calls `io`; writing files calls `fs`; there is no home where
  "file" is the unit. **task** — convergent: one designed file domain,
  surface spelled by the walker, not a generator.
- **`read-lines` is aspirational-flagged** — the `! line` effect shape is
  honest, the implementation slurps (`readToEndAlloc`, bounded by RAM); the
  tag makes it greppable. The same slurp+split loop is copy-pasted into
  `io:read-lines` — a mechanism duplicated across packages. **→009** — the
  line-split loop is a mechanism implemented twice; promote or fold when
  the file domain is unified.
- **The designed half is commented out.** `fs.kz:103-113` carries a
  phantom-typed `open`/`read`/`close` low-level API as a comment — "FUTURE".
  Meanwhile the handle-shaped file API that actually exists lives in the
  *runtime bridge* (`open`/`append`/`close` with held handles, exercised by
  kopium's notes scope) — the capability grew outside std because std's own
  sketch never landed. **task** — reconcile the commented sketch against
  the bridge's proven handle shape; one owns the other.

## Verdict

Evolved — two tors doing the minimum that callers needed when they were
written, while the file domain's real shape (handles, refusal, streaming)
lives in a comment and in the runtime bridge.
