## Seams

- **Three naming generations coexist in one file** — `readln`/`read.ln`,
  `eprintln`/`eprint`/`eprint.ln`, `print`/`print.ln`/`print.blk`. `println`
  already died by pin (`010_054`), so removal is a proven move, not a theory.
  **→019** — `eprintln`, `success`, `warn`, `args` are four dead tors the
  suite would never miss; `eprint` (entry, 0 uses) is the fifth candidate.
- **`read.ln` returns `""` on eof, error, and empty line** — three outcomes
  wearing one value; its own header admits "No error handling". The
  no-fallbacks law, violated inside std itself. **→010** — the arms exist in
  the same file (`readln` has them); the tor wants honest branches or removal.
- **Four overlapping stdin surfaces** — `readln` (a line, honest arms),
  `read.ln` (a line, lying arms), `read-stdin` (all of stdin), `read-lines`
  (stdin as a line stream). One domain, four spellings, three contracts.
  **task** — convergent: one designed input side.
- **The slurp machinery is copy-pasted three ways** — `io:read-lines`,
  `fs:read-lines`, and the `read-stdin`/`read-file` pair all hand-roll
  `readToEndAlloc` + `splitScalar` + the `\r`-trim + trailing-newline guard.
  **→009** — the read-loop is a mechanism implemented N times; promote it
  when the file/stdin domain is unified.
- **`[norun]` impl tors wear `pub`** — `print.impl`/`print.blk.impl` are
  shape-check targets that can never run, exported at the same rank as the
  user surface. The transform layer's internals are indistinguishable from
  the API in the pub list — the hidden-layer problem, visible in one file.
  **task** — a marker or a separate section; surface honesty, not a replay.
- **File/stdin split across io/fs** — cross-referenced from 001: `read-file`
  (110) lives here while `fs:write` (3) lives there. **task** — same designed
  file domain as 001's second seam; they are one finding.
- **Two `args` surfaces** — `io:args` (dead) vs `std/args` (live). **→019**
  with the dead set above.
